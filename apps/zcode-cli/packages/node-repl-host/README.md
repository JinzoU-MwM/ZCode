# @zcode/node-repl-host

The shared host for `node_repl`: the JS execution surface (a single tool, `js`) and the two domain
bridges (Browser Use, Computer Use) both live here.

## Why it is a standalone package

The host is **shared by the official capabilities** and does not belong to any single plugin. It used to live inside `browser-use-plugin`, with these consequences:

- changing Computer Use required touching the browser-use package;
- the CUA SDK and docs each had a hand-maintained copy inside browser-use;
- `resolveBuiltInNodeReplMcpServers` looked for the host artifacts only under browser-use's rootPath, so
  once the browser-use package was missing, CUA could not get the host even when enabled on its own.

The registration side was already consolidated in the CLI core (`bootstrap/src/app/built-in-node-repl.ts`, with the criterion
"bua or cua, either one enabled"); what was missing all along was **artifact ownership**. This package puts the source where it belongs.

## Artifacts are still carried by the plugin package

`dist/mcp/server.js` and `scripts/computer-use-client.mjs` are in the SEA release manifest
(`OFFICIAL_BROWSER_USE_REQUIRED_SEED_PATHS`), and their paths cannot move. So the browser-use build bundles its output from this
package's `src/server.ts`, and the CUA client/docs copies are generated by the build script rather than maintained by hand.
Moving the artifacts out of the plugin root as well requires changing the SEA manifest and bootstrap's hostPackage resolution at the same time, and is a separate step.
